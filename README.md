# Test-DevOps-EM

Микросервисное приложение, состоящее из HTTP-сервера на Python и прокси-сервера Nginx. Архитектура проекта полностью контейнеризирована с помощью Docker и разворачивается через Docker Compose.

## Быстрый запуск

Для запуска проекта вам понадобятся установленные **Docker** и **Docker Compose**.

1. **Запустите сборку и контейнеры в фоновом режиме:**
   ```bash
   run.sh
   ```

2. **Проверьте работу приложения:**
   Откройте браузер по адресу [http://localhost](http://localhost) или выполните команду в терминале:
   ```bash
   curl -i http://localhost
   ```
   **Ожидаемый ответ:** `Hello from Effective Mobile!`

3. **Остановка приложения:**
   ```bash
   down.sh
   ```

## Архитектура проекта и конфигурация

Проект разделен на два изолированных сервиса, которые общаются внутри выделенной Docker-сети.

### Структура файлов
```text
├── docker-compose.yml    # Оркестрация сервисов и настройка сети
├── nginx/
│   └── nginx.conf        # Конфигурация Nginx
└── backend/
    ├── Dockerfile        # Cборка Python-приложения
    ├── app.py            # Исходный код HTTP-сервера на Python
```

### Принятые инженерные решения 

#### 1. Backend
* **Отсутствие requirments.txt:** Приложение слишком просто и использование requirments избыточно, но если понадобится может быть добалено парок строк.
* **Запуск не от root:** Внутри контейнера создается изолированный системный пользователь `appuser`.

#### 2. Конфигурация Nginx
* **Фиксация версий:** Вместо тега `latest` используется конкретная стабильная версия `nginx:alpine` (так как весит очень мало и уже была у меня установлена).
* **Кастомный конфиг:** Конфигурация `nginx.conf` создана с нуля и прокидывается внутрь вонтейнера (можно добавить проброс внутрь файла, но тогда нужно создавать отдельный dockerfile для nginx что не сходится с требуемой структурой)
* **Корректное проксирование:** Настроен блок `upstream` для балансировки. Запросы на корневой путь `/` перенаправляются на backend

#### 3. Сетевое взаимодействие и Docker Compose
* **Изолированная сеть:** Создана отдельная bridge-сеть `effective_private_network`. Контейнеры изолированы от внешнего мира и общаются только друг с другом.
* **Service Names вместо IP:** Маршрутизация запросов от Nginx к backend происходит по имени сервиса (`backend:8080`) через внутренний DNS-сервер Docker.
* **Защита периметра:** Порт backend (`8080`) скрыт внутри сети. Наружу торчит порт `80` сервера Nginx.
* **Декларативность:** Контейнерам присвоены имена (`backend`, `nginx`).
